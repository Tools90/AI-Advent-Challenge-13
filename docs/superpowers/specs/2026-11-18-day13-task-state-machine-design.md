# Day 13 — Task State Machine

## Цель

Минимальное отдельное Go-приложение, в котором задача проходит фиксированные этапы, а переходы между ними проверяются кодом до изменения состояния. Ассистент может предлагать переход, но не может применить его самостоятельно.

## Границы

- Порт `8093`.
- Ключ DeepSeek копируется из Day 12.
- Без профилей, сложной памяти и паузы как отдельного состояния.
- Состояние задач, текущий шаг, история и чат сохраняются в `data/tasks.json`.
- При первом запуске создаётся демо-задача.
- «Очистить всё» возвращает приложение в состояние первого запуска.

## Этапы

Фиксированная последовательность:

```text
planning → execution → validation → done
```

| Этап | Текущий шаг | Ожидаемое действие |
|---|---|---|
| planning | Сформировать и утвердить план | Утвердить план |
| execution | Выполнить работы по плану | Сдать на валидацию |
| validation | Проверить результат | Валидация пройдена или не пройдена |
| done | Задача завершена | — |

## Разрешённые переходы

| Из | Действие | Куда |
|---|---|---|
| planning | approve_plan | execution |
| execution | submit_validation | validation |
| validation | validation_passed | done |
| validation | validation_failed | execution |

Любой другой переход запрещён. Проверка выполняется backend-кодом до мутации состояния.

## Модель данных

```text
Task
  id
  title
  description
  stage
  currentStep
  expectedAction
  messages[]
  history[]
  pendingProposal
  createdAt
  updatedAt

Proposal
  id
  action
  fromStage
  targetStage
  reason
  status: pending | accepted | rejected
  createdAt

HistoryEvent
  id
  at
  fromStage
  action
  targetStage
  result: applied | rejected | proposed
  reason
```

`currentStep` и `expectedAction` вычисляются из `stage`, а не задаются вручную.

## API

```text

POST   /api/tasks
POST   /api/tasks/select
DELETE /api/tasks/{id}
POST   /api/tasks/{id}/chat
POST   /api/tasks/{id}/confirm

POST   /api/clear-all
```

### Переход

`POST /api/tasks/{id}/transition`

```json
{ "action": "approve_plan" }
```

При успехе этап меняется, событие `applied` добавляется в историю.

При запрете:

```json
{
  "error": "переход запрещён",
  "from": "planning",
  "action": "complete_task",
  "allowed": ["approve_plan"]
}
```

HTTP-статус `409`. Этап не меняется, событие `rejected` добавляется в историю.

### Подтверждение предложения

`POST /api/tasks/{id}/confirm`

Сервер повторно проверяет `pendingProposal` по текущему этапу. Устаревшее или недопустимое предложение отклоняется, этап не меняется.

## Ассистент

Запрос к LLM содержит:

- название и описание задачи;
- текущий этап;
- текущий шаг;
- ожидаемое действие;
- разрешённые действия;
- последние сообщения чата;
- последние события истории.

Ответ ассистента — JSON:

```json
{
  "reply": "текст ответа",
  "proposedAction": "approve_plan",
  "reason": "почему предлагаю"
}
```

Правила:

1. Ассистент не меняет этап.
2. Ассистент может предложить действие, включая запрещённое, если пользователь прямо просит нарушить порядок.
3. Сервер проверяет предложение по таблице переходов.
4. Допустимое предложение сохраняется как `pendingProposal`; в чате появляется карточка подтверждения.
5. Пользователь подтверждает переход.
6. Запрещённое предложение не применяется: в чат пишется отказ, в историю добавляется `rejected`, возвращаются причина и список разрешённых действий.

## Реакция на отказ

После любого отклонения сервер делает отдельный вызов ассистента с контекстом:

- источник отказа: `user` или `server`;
- отклонённое действие;
- текущий этап;
- причина;
- список разрешённых действий.

Ассистент добавляет в чат короткий комментарий. Этап при этом не меняется. Если LLM недоступен, используется детерминированный fallback-текст.
## UI

- Слева: список задач, активная задача, «Новая задача», «Сбросить демо», «Очистить всё».
- Создание задачи: название и описание. План — фиксированная последовательность четырёх этапов.
- Сверху: этапы, текущий этап, текущий шаг, ожидаемое действие.
- Кнопки только разрешённых переходов.
- Чат выбранной задачи.
- Карточка подтверждения предложенного перехода.
- История переходов и отказов отображается в чате и в панели истории.
- Удаление задачи запрещено, если она последняя активная.
- «Очистить всё» удаляет все задачи и создаёт демо-задачу заново.

## Пауза

Отдельного состояния паузы нет. Текущий этап, шаг, история и чат сохраняются. После закрытия или перезапуска приложения работа продолжается без повторных объяснений.

## Тесты

- Все допустимые переходы.
- Все запрещённые переходы, включая `planning → done` и `execution → done`.
- Попытка подтвердить устаревшее предложение.
- Прямая просьба ассистенту нарушить порядок: переход не происходит, отказ в чате и истории.
- Сохранение и загрузка `data/tasks.json`.
- Отдельные состояние и чат у каждой задачи.
- Удаление последней активной задачи запрещено.
- «Очистить всё» создаёт только демо-задачу.

## Критерии готовности

- Этап нельзя изменить в обход таблицы переходов.
- Нельзя перепрыгнуть `planning → validation`, `planning → done`, `execution → done`.
- Ассистент предлагает, сервер проверяет, пользователь подтверждает.
- Запрещённая попытка видна в чате и истории.
- Состояние сохраняется между перезапусками.
- Приложение работает на `http://localhost:8093`.
